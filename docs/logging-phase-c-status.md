# 日志计划阶段 C 实施记录

日期：2026-10-29。范围：历史错误原因、请求编号和结构化日志；阶段 D 的可视化时间线、可开关运行指标及诊断页面仍未实施。

## 实现

- Flyway V8 为 `tasks`、`task_steps` 添加可空 `error_message_key`、`error_message_args` 和内部 `error_detail`，保留旧字段。任务失败及步骤失败在原事务中更新，现有记录不做批量重写。
- 新任务持久化安全文案键和内部原因。查询按 `Accept-Language` 返回安全文案；未知键或无法确认安全的旧文案回退通用提示，已知安全旧文案按原内容显示。当前参数字段预留且为 NULL。
- 个人任务接口不返回内部原因和参数；素材不存在、无权访问与丢失的对外提示保持统一。后台素材文件丢失可在内部原因中区分，不公开具体文件路径。
- 服务端生成请求编号并返回响应头与错误体；任务创建与派发事件可用请求编号关联，后台执行日志使用任务编号及阶段。线程执行结束恢复 MDC，成功轮询不逐次写日志。
- 控制台默认 ECS JSON；记录安全的身份、上传和任务事件，不主动记录请求体、Cookie、密码、验证码、联系方式、文件名或路径。框架非法路径警告定向降级，同时记录不含原始路径的可疑请求事件。业务日志调用失败不改变任务和请求结果。
- 配置集中在 Compose、`.env.example` 和后端配置：日志格式、业务日志级别、慢请求阈值及容器日志轮转可调整。HTTP 5xx 有请求编号时在错误提示中展示；无后端响应不伪造编号。

## 验证

- 新增测试先复现：任务失败没有文案键、旧表缺字段、响应头没有请求编号；实现后通过。素材受理后文件丢失的测试先发现原因过于笼统，再验证安全英文提示及内部原因。
- 独立 MySQL 测试：新失败任务及步骤的公开文案键、内部原因、英文查询和历史一致；不同用户不能读取；旧文案安全白名单和不可信值回退；三个阶段失败后停止后续步骤。
- 日志测试覆盖响应编号、身份／上传事件不包含模拟密码、邮箱、Cookie、文件名或非法路径；并发任务日志隔离、线程复用清理、日志故障注入与轮询降噪。真实容器日志检查成功关联五个任务的提交请求和工作线程。
- 创建独立 V7 数据库并写入模拟中文旧任务，使用旧版本读取；升级至 V8 后，新版本仍正确读取旧任务；随后切回阶段 B 旧镜像，旧版本在 V8 数据库上启动并读回同一任务。该演练只验证该旧镜像和记录，不代表所有历史版本或所有回滚场景都已验证。
- 完整 Docker 后端测试、MySQL 集成与格式检查通过，其中 45 项集成测试；前端格式、lint、类型、构建、4 项 Node 测试和 51 项组件／逻辑测试通过；错误目录一致性检查通过。
- 独立 Compose 通过基础接口、实际上传、用户隔离、异步成功及三阶段失败检查。CI 配置已包含现有检查入口，尚未在 GitHub 实际触发。
- 演示环境迁移前建立了仅当前用户可读取的数据库备份；更新后服务健康，Flyway 版本为 V8，原有 12 条成功任务仍在。原数据库卷和素材卷均保留。

## 限制

- 仅错误文案支持中英文；旧历史文案没有记录文案键，不保证自动翻译。历史中无法确认安全的文案仍存库但不会直接展示。
- 未覆盖所有第三方依赖在自定义日志配置下的输出；修改框架、MyBatis 或代理日志级别前需要重新审查敏感信息。日志轮转或容器删除可能使旧日志不可用，日志不作为持久审计记录。
- 阶段耗时页面展示、JVM 指标开关和受控诊断页属于阶段 D；整体发布前的最终交付验收属于阶段 E。
- V8 是追加列，不自动反向迁移。回滚时保留数据库和素材卷，并提前备份；阶段 B 旧版本无法处理新字段，只能读取旧字段。服务重启后未完成任务仍会标记失败，不自动续跑。
