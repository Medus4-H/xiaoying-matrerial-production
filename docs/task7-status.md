# Task 7：任务跟踪、历史与结果

日期：2026-10-28。本阶段完成任务状态跟踪和历史、详情及结果预览页面。下文为本阶段快照；此前未捕获的真实连接中断和终态停止查询已由 [Task 8](./task8-status.md) 补充验证，最终交付验收仍属于 Task 9。

## 已实现

- 共享布局中的任务跟踪器在访客身份有效后读取全部未结束任务，每个任务独立查询服务端状态。受理的新任务立即加入跟踪器和当前模板记录；卡片本身不创建轮询。
- `QUEUED` 和 `RUNNING` 定时查询，`SUCCEEDED`、`FAILED` 停止自动跟踪；没有未完成任务时不发周期请求。页面隐藏时暂停定时查询，回到前台后恢复未结束任务。
- 查询失败或超时保留最后一次任务状态、更新时间及错误，提供“恢复查询”；不会把查询异常当成制作失败。全部活动任务的初始化请求失败会单独显示重试入口。
- 刷新后从 Java 的全量 active 接口恢复跟踪，不受历史分页限制。访客失效、改变或页面卸载时取消请求和定时器，旧响应不能更新当前访客。
- 模板详情右侧显示当前模板记录，`/history` 显示分页历史，`/tasks/{id}` 显示任务和步骤；成功任务展示缩略图并支持弹窗预览，失败展示原因。预览支持 Escape 和焦点返回。
- 历史响应优先使用已有任务快照，不能使已完成任务退回处理中；新受理任务会立即显示。分页合并按照创建时间与任务 ID 排序并限制页长。
- 轮询间隔、查询超时和历史页长可在环境配置调整；这些前端构建配置修改后需重新构建镜像。
