# 日志计划阶段 D/E 实施与验收记录

日期：2026-10-29。阶段 D 的功能已实现；阶段 E 的自动化和隔离容器验证已执行，未覆盖的人工或环境验证列于下方。

## 阶段 D：实现

- 任务详情复用服务端步骤起止时间，展示已结束步骤的耗时；缺失、无效和倒序时间显示不可用，跳过或未结束的步骤不计算耗时。
- 任务执行线程记录单调时钟的排队等待和阶段耗时，以及队列深度和活跃线程快照。可选的 JVM 堆和 GC 全局累计采样默认关闭，不可用的 GC 计数或时间不伪装为零；采样异常不影响任务。
- 独立诊断接口默认关闭。显式启用时必须使用 `demo,diagnostics` profile，不能与 `prod` 或 `production` 同时启用，并检查配置范围。诊断会话独立于普通用户，使用随机令牌、服务端哈希保存、限时过期、限制会话及尝试次数；建立会话和退出均校验来源。
- 白名单事件存入有界内存缓冲，限制单条大小，满时淘汰最旧事件；无法立即获取锁时丢弃，不等待业务线程。不会提供原始消息、异常堆栈或请求体。页面支持按请求编号、任务编号、级别与时间筛选，以及读取当前快照。事件只代表本实例，非审计记录。
- 新诊断错误码和中英文文案加入现有版本化目录及回退目录；错误语言包版本更新为 2。诊断配置、独立本机覆盖文件、操作和回滚说明见 README。

## 阶段 E：本次验证

所有构建、项目脚本、测试和应用运行均在 Docker 内执行；使用独立的 `xiaoying-logging-de` 项目、数据卷和端口，未重建原有演示服务。原有演示数据库最后只读检查时有 22 条任务；这只是检查时的数量，并非独立备份证明。未执行删除任何数据卷的命令。

- `compose.check.yml` 前端检查：格式、lint、TypeScript、Node/Vitest 测试及生产构建；覆盖多任务、查询异常与执行失败的区别、身份切换，以及阶段耗时边界。
- `compose.check.yml` 后端 `mvn verify`：Spotless、单元测试、45 项 MySQL 集成测试及打包通过。错误目录独立一致性检查通过。
- 空白隔离 Compose 数据库启动成功；基础接口、素材上传与访问隔离通过。模拟任务检查覆盖成功、三个指定失败阶段、并发任务、历史恢复接口、结果图片和跨访客隔离。
- 默认设置下诊断事件接口返回 404。显式启用后，通过 Next.js 代理验证未授权拒绝、独立凭据、错误来源、限流、筛选、退出失效、无缓存、运行快照及凭据不出现在事件或容器日志中。单元测试覆盖到期、无效配置、生产 profile 禁用、白名单过滤、事件淘汰和采样异常。
- 容器日志检查证实请求编号可关联任务受理和后台阶段、包含排队及 JVM 快照、快速成功轮询无逐条 INFO 日志，测试文件名和诊断凭据没有进入检查到的日志。检查时 Docker `json-file` 配置为 `10m`、3 个文件；隔离诊断端口确认仅绑定 `127.0.0.1`。
- 独立只读审查指出不支持的 GC 指标被当成零、诊断错误未走统一目录，以及凭据长度不能证明随机性；已分别修正代码、增加测试或在 README 澄清。当前实现只校验凭据长度，使用者仍需生成高熵凭据。
