# 素材制作网站：设计与验收规格

日期：2026-10-28。状态：设计基线；架构、身份、模板、素材上传及任务后台 API 已实现；上传、提交、任务跟踪及历史界面已实现；最终交付验收待完成。当前验证结果以 Task 3—7 记录为准。项目根目录：`./`。

## 1. 目标、优先级与范围

用户浏览模板、上传素材、提交任务后可继续操作网站，Java 在后台依次执行素材检查、模拟生成、结果整理；用户可查看个人历史、阶段、结果或失败原因，刷新后继续跟踪未完成任务。

优先级：异步业务闭环与状态正确性 → 上传与身份隔离 → 核心测试与容器交付 → 视觉完善。实现复杂度和工作量不是质量指标。

交付覆盖 R-01—R-14，包括推荐的 Compose。六个模板、三个分类、1/2/3 张素材要求足以演示。图片只接受 JPEG/PNG，默认每张最大 5 MiB（5242880 字节）；模板可配置更低限制。

不做：真实 AI、支付、积分、会员、第三方账号、国际化、视频、模板 CRUD、独立管理后台、MQ、Redis、多实例、任务重试/删除、下载按钮、断点续跑、重启后自动恢复执行。成功结果支持图片预览。开发工具只提供可控失败、耗时调整和现有步骤记录展示，不建立额外管理应用。

## 4. 身份与授权

1. 前端身份 Provider 单次 GET /api/me；401 时集中 POST /api/session，避免多个组件并发创建身份。
2. Java 生成 256 位随机令牌；HttpOnly Cookie 保存原令牌，users 表仅存 SHA-256 哈希。
3. Cookie 使用 Path=/、SameSite=Lax；HTTPS 部署 Secure，明确有效期并与数据库 expires_at 一致。
4. POST /session 有有效令牌时复用身份。业务 GET 不隐式创建用户。
5. 写接口校验允许的 Origin；身份来自 Cookie，不接受 userId 作为授权依据。
6. 任务、素材和结果均按当前用户授权；不存在或无权限统一 404。公开模板封面可以不要求身份。
7. 普通窗口与隐身窗口演示两个身份，不提供切换按钮。会话失效时暂停任务查询，提示建立新访客身份；未经提示不把旧记录显示到新身份。

限制：清除/过期 Cookie 后无法找回旧身份，不支持跨设备，不等同完整账户系统。客户端用户 ID 仅用于缓存命名，不能授权。

## 5. 数据模型

主键统一 UUID 字符串；内部存储键为服务器生成的相对路径，绝不接受客户端磁盘路径。时间 UTC、DATETIME(3)，API ISO-8601 带 Z。金额和积分不建模。

| 表 | 字段 |
| --- | --- |
| users | id、session_token_hash、created_at、expires_at |
| templates | id、title、category_id、category_name、description、cover_key、required_image_count、accepted_mime_types JSON、max_file_size_bytes、preset_result_key、sort_order |
| assets | id、user_id、storage_key、original_name、mime_type、size_bytes、width、height、created_at |
| tasks | id、user_id、template_id、template_title_snapshot、requirements_snapshot JSON、status、current_stage nullable、failed_stage nullable、error_code nullable、error_message nullable、result_key nullable、simulation_snapshot JSON、created_at、started_at nullable、finished_at nullable、updated_at |
| task_assets | task_id、asset_id、slot_index |
| task_steps | task_id、stage、sequence、status、started_at nullable、finished_at nullable、error_code nullable、error_message nullable |

索引/约束：users token hash 唯一；task_assets(task_id,slot_index) 唯一；task_steps(task_id,stage) 唯一；tasks(user_id,created_at,id)、tasks(user_id,status)；assets(user_id)；必要外键。素材 ID 列表不得重复，数量必须等于模板要求；槽位顺序从 0 开始。

Flyway：V1__schema.sql 建表，V2__seed_templates.sql 初始化三个分类、六个模板。分类由模板分类字段去重读取，无独立分类管理表。模板修改不影响已创建任务的标题和要求快照。MySQL 不另外执行一套重复 DDL 初始化。

## 6. API 契约

成功直接返回业务对象。错误为 {code,message,fieldErrors?,requestId}。业务与 HTTP 错误分离：参数 400、未认证 401、不存在/无权限 404、请求过大 413、基础设施错误 5xx。任务执行 FAILED 仍是查询成功的 200。

| 方法/路径 | 输入 | 输出 |
| --- | --- | --- |
| GET /api/me | Cookie | {id,displayName,expiresAt}，无身份 401 |
| POST /api/session | 无业务参数 | 同 me；Set-Cookie；新建 201、复用 200 |
| GET /api/categories | 无 | {items:[{id,name}]} |
| GET /api/templates | categoryId 可选 | {items:TemplateSummary[]} |
| GET /api/templates/{id} | 模板 ID | TemplateDetail |
| GET /api/templates/{id}/cover | 无 | 本地封面图片 |
| POST /api/assets | multipart file | 201，AssetResponse |
| GET /api/assets/{id}/content | Cookie | 当前用户图片 |
| POST /api/tasks | CreateTaskRequest | 202，TaskSnapshot |
| GET /api/tasks/active | Cookie | {items:TaskSnapshot[]}，全部未结束任务 |
| GET /api/tasks | page 默认 1、pageSize 默认 20/最大 50、templateId 可选 | {items:TaskSnapshot[],page,pageSize,total} |
| GET /api/tasks/{id} | Cookie | TaskSnapshot（含 steps） |
| GET /api/tasks/{id}/result | Cookie | 仅成功且有权限时返回结果图片 |

TemplateSummary：id/title/categoryId/categoryName/coverUrl/requiredImageCount。TemplateDetail 增加 description/acceptedMimeTypes/maxFileSizeBytes。

AssetResponse：id/previewUrl/mimeType/sizeBytes/width/height。CreateTaskRequest：templateId/assetIds（有序）/simulation（仅开发允许）。TaskSnapshot：id/templateId/templateTitle/status/currentStage/failedStage/errorCode/errorMessage/resultUrl/createdAt/startedAt/finishedAt/updatedAt/steps。steps 包含 stage/sequence/status/startedAt/finishedAt/errorCode/errorMessage；nullable 字段统一返回 null。

静态 /active 路径不得被 /{id} 错误匹配。历史按 createdAt DESC、id DESC 稳定排序。分页查询不是全量 active 的替代品。

## 7. 上传与文件存储

- 页面每槽位独立维护 selectedAsset、candidatePreview、uploadStatus、error、requestVersion 和 AbortController。
- 选择前校验 MIME、大小；选择后上传；任务只传服务端素材 ID。
- 替换中保留旧素材，新上传成功才切换；替换失败仍保留旧素材。任意槽位上传中禁止提交。
- 移除/再次替换递增 requestVersion 并 abort；晚到响应不得覆盖新选择。卸载时释放 object URL。
- Java 限制单文件 5 MiB、单请求 6 MiB；读取实际格式并解码校验，最长边不超过 8192、总像素不超过 1600 万。先检查尺寸再全量解码。
- 通用上传校验后，接单时按模板再次验证数量、实际 MIME、大小、素材归属及文件可用性。
- 生成存储键，使用临时文件加同文件系统发布；写库失败尽力删除新文件。原文件名仅作展示，转义后输出。
- 本地目录：data/uploads、data/results、data/tmp；模板封面与预置结果来自仓库 demo-assets，随镜像打包。
- 用户文件不映射为公开静态目录，始终经过 Java 授权端点；正确 Content-Type、nosniff。
- 移除仅解除表单引用，不删除已上传文件；首版不自动清理孤立素材/中间文件，README 说明磁盘增长限制。

## 8. 状态机与执行边界

整体：QUEUED → RUNNING → SUCCEEDED / FAILED；QUEUED 也可因分发失败直接 FAILED。终态不可返回处理中。

阶段：ASSET_CHECK → GENERATE → FINALIZE；排队 currentStage=null，完成保留最后执行阶段。步骤初始 PENDING，执行时 RUNNING，结束 SUCCEEDED/FAILED；失败后尚未执行的步骤为 SKIPPED。

| 操作 | 数据库边界 |
| --- | --- |
| 创建 | 一个事务写 tasks、task_assets、三条 task_steps |
| 领取 | 条件更新 WHERE status='QUEUED'；影响行数必须为 1 |
| 阶段开始 | 一个短事务同时写任务阶段和当前步骤 RUNNING |
| 阶段完成 | 一个短事务写步骤 SUCCEEDED |
| 最终成功 | 结果文件准备好后，同事务写 FINALIZE 成功及任务 SUCCEEDED/result_key |
| 阶段失败 | 同事务写当前步骤 FAILED、后续 SKIPPED、任务 FAILED 及原因 |

每条状态更新携带预期状态/阶段条件，失败时不能无条件覆盖终态。数据库事务不覆盖延迟、文件复制或整个制作过程。

接单使用 TransactionTemplate 显式提交后 executor.execute(() → run(taskId))，不传请求、连接和文件流。默认 ThreadPoolTaskExecutor 2 个线程、队列 20、AbortPolicy。不得使用 CallerRunsPolicy 或手工无限创建线程。

队列拒绝：新事务记录 FAILED/DISPATCH_REJECTED，failedStage=null，全部 PENDING 步骤 SKIPPED；仍返回 202 任务快照，前端据服务端状态展示。若持久化失败，则返回基础设施错误并提示先查历史，不假装已经可靠受理。

Runner 显式顺序编排三个方法，不搭通用插件工作流。开始更新/完成更新失败都终止当前运行，不在内存中伪装成功。

1. 素材检查：写阶段 → 按快照验证文件 → 延迟/故障注入 → 写完成。
2. 模拟生成：写阶段 → 延迟/故障注入 → 将模板预置图片复制为临时产物 → 写完成。
3. 结果整理：写阶段 → 延迟/故障注入 → 将产物发布到任务专属最终路径 → 同事务写步骤与任务成功。

预置结果与上传内容无真实生成关系，需要在 UI/README 说明为模拟。不能用浏览器延迟切文字替代后台步骤。

## 9. 模拟控制、关闭与重启

开发 profile 允许 simulation={failAt:null|ASSET_CHECK|GENERATE|FINALIZE,assetCheckDelayMs,generateDelayMs,finalizeDelayMs}。每段 0—30000 ms，默认 1000/6000/1000；未知阶段和超范围参数 400。正式 profile 对非空 simulation 明确返回 400/SIMULATION_DISABLED。

每次接单保存完整默认值归一化后的快照，后续全局配置变化不改变已有任务。指定阶段开始、执行其延迟后再抛可读失败，不随机失败。

开发面板为制作页折叠区，只在允许模拟配置时显示；不得把用户提交的普通 Cookie 当管理员权限。正式环境关闭服务端模拟入口才是边界。

单实例启动、接受请求前将旧 QUEUED/RUNNING 标为 FAILED/SERVER_RESTARTED：原 RUNNING 步骤失败，剩余 PENDING 跳过，已成功步骤保留。系统中断 failedStage=null，currentStage 可保留供排查。不重跑、不重新排队。

关闭时停止接单并停止接收新执行单元；等待正在运行任务的宽限期有上限，不能声称队列全部保证完成。容器强杀遗留任务由下次启动收尾。数据库不可写时无法保证记录失败，输出带 taskId 的日志并如实列为限制。

## 10. 前端状态与轮询

服务端 TaskSnapshot 与 QueryError 分开，不维护第二份可随意修改的任务状态。上传状态、提交请求状态、后台任务状态互不混用。

- queryKey：['tasks',userId,'detail',taskId]、['tasks',userId,'history',templateId,page,pageSize]、['tasks',userId,'active']；模板 key 带分类。
- 一个共享布局 TaskTracker 恢复全部 active，受理后立即 registerTask(snapshot)，每任务仅一个拥有轮询配置的 observer。
- 详情、卡片读取同 key 缓存的 observer 关闭 interval、自动聚焦/挂载查询，不各自轮询；需要缺失数据时由 tracker 负责首次查询。
- 间隔 2000 ms，只为 QUEUED/RUNNING 设置；终态 interval=false，并关闭终态聚焦/重连/挂载自动获取。
- 网络异常后暂停该任务自动轮询，保留已有快照、上次更新时间和可读提示；点击“恢复查询”成功后按服务端状态继续或停止。retry=false，避免隐藏重试掩盖验收行为。
- 默认后台标签页暂停周期轮询，回到前台只刷新未结束任务；Java 执行不受影响。
- active 初始化失败显示重试入口，不把空列表当成无任务。
- queryFn 消费 AbortSignal；身份变化取消并移除旧用户查询，清理跟踪集合；返回结果还需身份世代校验，防止取消不及时串用户。
- 历史响应不直接覆写已有单任务缓存；已有详情缓存优先。历史翻页无需重建 tracker。
- 任务终态从跟踪集合移除，失效相关历史查询一次以更新结果；无待处理任务不发周期请求。
- History 刷新是主动请求，可刷新已结束记录；不重新制作。正在查询时按钮防连点。

提交按钮：缺素材/上传中/当前提交中禁用；202 返回后清除 submitting，注册任务并插入右侧列表，保留素材选择以便连续演示。提交结果未知时不自动重提，提示先检查历史；不实现强幂等。

## 11. 页面、交互和无障碍

| 路由 | 内容 |
| --- | --- |
| / | 导航、分类、模板网格、加载/空/失败状态 |

处理中展示“第 2/3 步：模拟生成”，不伪造百分比。失败写阶段与原因；系统失败写系统原因。查询异常有独立提示。卡片显示创建时间，成功可打开图片预览。

语义按钮/文件输入、图标 aria-label、图片 alt、可见 focus、对话框焦点管理/Escape/关闭后归还焦点、状态 aria-live。状态不只靠颜色。上传点击为必备，拖拽可不实现。字体使用本地/系统字体，构建不下载远程字体。

## 12. 测试与运行证据

Java 单测替换 DelayProvider 和存储依赖；不为验证顺序真实等待。真实 MySQL 集成测试验证 Flyway、Mapper、条件更新和归属；不使用 H2 冒充 MySQL 行为。

| 后端行为 | 断言 |
| --- | --- |
| 正常与三阶段失败 | 正确顺序；失败后零次调用后续阶段；快照和步骤一致 |
| 提交异步 | runner 被闸门阻塞时 submit 仍能返回任务 ID |
| 重复领取 | 同一任务仅一次成功领取 |
| 队列拒绝 | 明确系统失败，无永久等待 |
| 上传/归属 | 伪扩展名、超限、坏图、重复素材、其他用户素材被拒 |
| 查询纯读 | 连续查询不推动状态，终态不回退 |
| 重启收尾 | 已成功步骤保留，其余明确失败/跳过 |

前端使用 MSW、虚拟时钟和可控 Promise：A 成功/B 处理中互不覆盖；查询异常保留旧值；执行失败可读；恢复继续；终态及无任务零周期请求；历史分页外 active 恢复；切身份晚到响应隔离；上传替换乱序；卸载取消；提交后恢复可用。
