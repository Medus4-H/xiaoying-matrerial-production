# 可选联系方式注册与绑定

## 参考与范围

本地 VergeX 的 Web 注册先验证邮箱、再设置密码；邮箱和密码用于登录。它另有安全邮箱绑定流程，要求已有身份凭据和新邮箱验证；未发现该 Web 注册流程要求同时填写手机号。该项目包含真实发送、验证、限流与更复杂的安全流程，本项目不复制代码。

参考 [Supabase Auth](https://github.com/supabase/auth) 的邮箱或手机登录及登录后更新用户资料，以及 [Auth.js 的账号关联说明](https://github.com/nextauthjs/next-auth/blob/main/packages/core/src/providers/oauth.ts) 避免不可信的自动账户合并。仅借鉴行为，不引入依赖或复用源码。

## 方案

- 注册选择邮箱或手机号其中一种，输入对应模拟验证码和密码；默认新建独立用户，不继承访客记录；仅明确勾选导入后才将当前有效访客升级并沿用其用户 ID。原双字段注册协议保留兼容，不影响已有客户端。
- 注册后在账号信息中显示两种联系方式；未绑定的另一种可填入并绑定。绑定需对应模拟验证码和有效账号会话，不要求再次输入密码；已有联系方式不提供修改、解绑或合并。
- 邮箱与手机号分别按当前保存值唯一；数据库条件更新与唯一约束同时防止覆盖和并发抢占。手机号仅去除首尾空格，不自动归一化国家区号和不同写法，须使用一致写法。成功绑定后两种方式均可用原密码登录，用户 ID 和资料保持不变。
- 使用新增 V6 迁移将联系字段设为可空，保留 V5 数据及索引；已有双联系方式账号保持不变。
- 验证码仅演示，不证明联系方式真实归属；非 demo 环境禁用演示注册和绑定，不支持实际发送或密码找回。

## 检查

容器测试覆盖两种独立注册、绑定及两种登录、绑定占用冲突、错误验证码、游客无权绑定、已有字段不可覆盖、既有双字段账号仍可登录、原资料与账号隔离；前端测试覆盖选择渠道与绑定流程；执行完整构建和回归。

## 绑定流程调整

根据后续用户要求，绑定联系方式时不再输入或校验账号密码；会话、验证码和唯一约束继续生效。注册和登录仍使用密码。旧客户端发送的 `password` 字段仅为协议兼容而被忽略。模拟验证码不验证联系方式的真实归属，不能用于生产；上线前需接入真实验证码并重新评估会话安全。2026-10-29 容器回归通过前端格式、lint、类型检查、39 项 Vitest、4 项 Node 测试和构建；Java 完整 verify 通过，含 25 项 MySQL 集成测试。


## 访客和账号隔离调整

根据 2026-10-29 用户反馈，原先自动升级访客会把共用浏览器中上一个访客的记录带入新账号，已改为默认分离，注册时可明确选择导入自己的访客资料。浏览器暂存一个有效访客会话，切换到账号不会导入记录；退出账号可恢复访客，访客仍受会话过期和浏览器数据清除限制。旧页面通过身份一致性校验、跨标签页通知及回到页面时重新确认身份，避免展示或操作其他账号的数据。`visitor_recoveries` 仅保存明确授权分离的旧访客资料的一次性恢复关系。
