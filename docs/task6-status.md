# Task 6：图片上传和提交页面

日期：2026-10-28。本阶段完成模板详情页上传与任务提交；任务状态的持续更新、完整历史和结果预览由 Task 7 实现。

## 已实现

- 模板详情按 Java 返回的图片数量生成槽位，按返回的类型和大小进行客户端校验。选图后立即上传到 Java，成功后使用受保护的服务器图片地址展示；服务端继续进行独立校验。
- 每个槽位支持预览、替换、移除、上传中和失败提示。替换时保留旧素材，成功才切换；失败保留旧图。更换和移除会取消旧请求并检查版本，避免旧响应覆盖新选择。组件卸载或访客身份变化时取消请求并释放临时预览地址。
- 素材未准备好、正在上传或提交时禁止提交；接单成功后解除提交中状态，保留素材以便再次提交。当前页面展示受理快照及任务编号，不模拟后台进度。
- 请求网络异常、HTTP 408 或服务器错误时，提示受理结果未知，不自动重试。历史页面尚未接入，当前提示明确说明这一限制；可通过任务 API 查看记录。
- 可通过 `NEXT_PUBLIC_SHOW_SIMULATION_CONTROLS=true` 在演示环境显示失败阶段选择；此项为前端构建配置，修改后需要重新构建前端。`APP_PROFILE=prod` 的后端仍拒绝模拟参数。阶段耗时通过 `TASK_*_DELAY_MS` 配置。

## 验证

- `docker compose -f compose.check.yml run --build --rm frontend-check`：格式、lint、类型、4 项 Node 测试、16 项组件测试和生产构建通过。新增测试覆盖类型/大小及可配置限制显示、上传和提交状态、替换失败、旧响应、移除、未知提交结果及 HTTP 408、模拟参数、卸载清理和访客身份变化。
- 在独立 Compose 演示环境使用项目随附示例图，经浏览器完成 1、2、3 张图片模板的上传与提交；验证已上传素材可连续提交两个任务。双图任务指定 GENERATE 阶段失败，在隔离数据库中确认 `FAILED/GENERATE/SIMULATED_FAILURE`；普通任务确认成功。
- 页面当前只展示本次打开期间的受理快照，无法自动追踪进度；刷新恢复、历史与结果展示属于 Task 7。GitHub 托管 CI 尚未实际运行。

## 取舍与限制

- 沿用现有 React Query 身份上下文和浏览器原生文件输入；临时预览仅用于上传期间，不作为后端素材。模拟控制默认关闭，不提供独立管理后台。
- 未引用的上传文件暂不自动清理，可能产生磁盘增长；提交请求结果未知时没有幂等键，不自动重复提交。
- 匿名身份过期或清除后无法找回旧资料仍为 TODO；本阶段没有修改身份策略。实际投入未精确计量，不能以计划时间替代。
