# 账号与访客记录隔离修复

日期：2026-10-29。

## 原因与方案

旧注册实现直接把浏览器当前访客升级为账号，会将注册前的访客素材和任务自动纳入新账号。共用浏览器时，这些记录可能属于其他访客。现改为默认新建独立账号；仅用户在注册时明确选择导入本人访客资料，才沿用访客身份。未导入时，浏览器暂存原访客会话，退出账号后可恢复；匿名会话过期或浏览器数据被清除后仍无法保证找回。已有账号登录时同样不合并访客资料。

同一浏览器的其他标签页切换账号时，通过通知及回到前台重新确认身份来更新界面；确认期间隐藏个人历史。素材、任务、注册、绑定和退出请求携带当前页面的用户标识，服务端以 Cookie 为身份依据并核对一致性，不一致返回 IDENTITY_CHANGED。该标识不是认证凭据；用户隔离依然由服务端的 Cookie 身份和记录归属共同保证。

## 已有数据处理

用户明确选择将当前账号中的注册前访客资料移出并保留。执行前检查该资料不被后续账号任务引用、没有任务正在运行，并备份数据库；在独立测试库演练了成功分离及引用冲突时回滚。随后将一条旧访客任务和其一份素材转入独立访客，保留结果文件及关联。核对当前账号旧访客任务为 0、访客任务及素材各为 1、任务和素材归属一致。该账号退出时会一次性恢复已分离的访客身份；若浏览器另有有效的待恢复访客，会先恢复它，分离出的访客可在后续登录该账号并退出时恢复。

## 验证

- 前端 Docker 完整检查通过，包括格式、lint、类型、44 项 Vitest 和 4 项 Node 测试及构建；覆盖同标签页退出登录、跨标签页切换、连续切换和旧页面请求隔离。
- Java Docker 完整 verify 通过，含 30 项 MySQL 集成测试；覆盖默认分离、主动导入、访客恢复、跨用户任务与素材访问和旧页面请求拒绝。
- 独立 Compose 环境通过真实 Next.js 代理、Cookie 和 MySQL 验证，创建访客记录，分别切换两个账号，检查历史、任务详情、素材读取和访客恢复。临时环境及数据卷已清理；原演示数据卷保留。
- 一次性本机数据库备份包含个人数据，不随源码交付；访客持久身份、密码找回、真实验证码等仍未实现。
