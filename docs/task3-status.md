# Task 3 与身份过期提示实施记录

日期：2026-10-28。

## 已实现

- POST /api/assets 接收文件并校验身份、来源、声明类型、实际内容、大小、最长边和总像素；服务器生成文件名，写入临时文件后原子发布到数据卷，数据库保存素材元数据。
- GET /api/assets/{id}/content 按当前访客归属读取，其他访客及不存在的素材均返回 404；响应不缓存且设置 nosniff。
- 写数据库失败时尽力删除刚保存的文件。提供 `requireOwnedAssets` 内部方法以便 Task 4 校验数量、重复项、类型、大小、归属和文件可读性；该方法尚未接入任务接口。
- 图片限制集中在环境配置，提供本地 JPEG 示例。超大上传在真实代理路径返回 413 和可理解的提示。
- 长时间打开页面后，身份到期显示提示，主动选择才能创建新访客；焦点或可见状态恢复时重新检查，慢身份请求以当前时间计算剩余时间。页面刷新且 Cookie 已过期时，首次访问仍会建立新访客，旧身份不可找回。

## 验证证据

- 上传 API 尚未实现时，隔离 MySQL 集成测试出现预期 404；实现后通过。
- 慢身份请求的回归测试先失败再通过；真实超限请求先出现不明确的 413 文案，修正后通过。
- 最终 Java：6 项单元测试、5 项独立 MySQL 集成测试，格式检查和构建均通过。覆盖 JPEG/PNG、损坏内容、类型不符、字节数、最长边和总像素超限、来源、无身份、跨访客访问、文件缺失、素材约束以及数据库写入失败后的清理。
- 最终前端：4 项单测、格式、lint、类型和构建通过；短会话的真实浏览器测试观察到到期提示和用户主动建立新访客。
- 隔离容器通过 Next 代理上传本地示例图片，原文件字节可由本人读取，其他访客不可读取；真实超限请求返回 413 和明确文案。
- 在独立环境中重启后端前后，素材记录和数据卷文件均为 3 条/3 个；该检查证明记录和文件仍在，未用同一会话再次读取旧素材。
